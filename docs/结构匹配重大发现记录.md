## 一、数据解析层（gt 与数据源）

### 1.1 gt 的正确来源
- **之前用错 gt**：拿 `t_voice.tbl` 的 ch 记录（15,558 条）当 gt，方向偏了。
- **正确 gt = `match_result.csv`**：47,063 行（= Remake 总台词 47,063 + header），其中
  - `matched` 28,680 条（Remake 台词 → EVO voice_id，人工校对结果）
  - `voiceonly` 378 条（脚本外语音）
  - `unmatched` 18,005 条
- README 后半段「历史匹配统计」：1st 总匹配数 29,180、人工校对 27,537。

### 1.2 EVO msg 的三个解析坑（都修复）
1. **跨行解析**：`ChrTalk #N` 和 V voice_id 不在同一行（隔 speaker 和空行）。
2. **多段 [x02]**：一个 `ChrTalk #N` 块可含多段 `[x02]`，每段一个 voice_id。
3. **talk_num 偏移**：`_1/_2` 变体场景里 py 从 0 重新编号、msg 保留连续编号，须按**顺序位置**对应（不能按 talk_num 相等）。
4. **lambda 异步任务污染**：`lambda_57EA` 等被 `QueueWorkItem2` 入队的 lambda，内部 label/Jump 污染主流程，须排除 `lambda_` 前缀的 FunctionDef 和所有 Lambda。

**成果**：未关联 V 从 10,079 降到 226（0.77%）。

### 1.3 语音编号体系
- **v 记录 = Remake 自带语音**：`v{角色码}_{类型}_{序号}`（如 v015_00_0001），类型有数字(00-04)+字母(bv/gs/gy 等)。
- **ch 记录 = EVO 匹配语音**：`ch{角色码}{region}{seq}`（如 ch1060150028）。
- 两套编号只有「角色码」共通，其余维度不对称，**无法靠编码规律直接对应**，必须靠人工校对桥接。

## 二、场景对应层

### 2.1 场景文件名编码规律
- **EVO**：`前缀(C城市/T主剧情/R道路/E结局) + 章节号(千位) + 序号 + 变体`
- **Remake**：`mp + 章节号 + 序号 + 变体(_01~_22子场景/_ev/_extk)`

### 2.2 章节号严格对应
```
mp0xxx → EVO 章节 0（序章）
mp1xxx → EVO 1  ...  mp4xxx → EVO 4
mp8xxx → EVO E（结局）
```
无一跨章节例外。

### 2.3 场景对应（锚点投票）
- TOP1 命中 **91.7%**，完整召回 56%，多对一场景完整覆盖 40%。
- **硬章节过滤是负收益**（91.7%→90.8%），因为 gt 有跨章节台词复用。

### 2.4 场景多对一合并
- Remake 173 场景 ↔ EVO 484 场景（约 2.8:1），Remake 合并了 EVO 场景。

## 三、结构重建层（控制流）

### 3.1 条件分支语义镜像（关键）
- **Remake 用 `JumpWhenFalse`**（假分支跳转、真分支 fallthrough）
- **EVO 用 `Jc`**（真分支跳转、假分支 fallthrough）
- **图匹配时必须交换语义**：Remake `cond_false` ↔ EVO `cond_true`

### 3.2 两边结构（重建后）
| | 场景 | 函数 | 块 | 边 | 台词 |
|---|---|---|---|---|---|
| EVO | 491 | 5,947 | 29,438 | 54,480 | 33,735 语音 + 25,374 无语音 |
| Remake | 173 | 17,675 | 23,046 | 32,429 | 46,016 |

边类型统一：`jump + cond_true + cond_false + next(顺序fallthrough) + switch(EVO Switch case)`

### 3.3 Remake fallthrough 解析 bug（修复）
- `JumpWhenFalse/True` 是**块内条件跳转**（假/真分支跳转、另一分支 fallthrough 继续），**不是块尾**。
- 块尾只有 `JUMP` 和 `Return`。
- 修复后：有台词块 6,486 → 10,737（之前真分支台词被错堆进 `_entry`）。

### 3.4 Remake 台词 <...> 控制码
- `<k>`对话选项、`<P1/P2>`换行、`<R>/</R>`注音、`<C1/C2>`颜色、`<W>`等待、`<S>`表情，共 8,000+ 处，须正则 `re.sub(r'<[^>]*>', '', text)` 去掉。
- 去掉后锚点 +7,390。

## 四、结构匹配层（图匹配）

### 4.1 块级对齐
- 锚点投票：1:1 对齐 **77%**（有锚点块），1:N 候选 23%。
- 1:N 按「锚点 EVO 块变化点」拆分：**100% 拆成 1:1**，gt 段级正确率 89.7%。

### 4.2 沿边传播
- 从已对齐块沿边(语义镜像)迭代传播，+2,639 块。
- 覆盖率 **83.4%**（8,957/10,737 有台词块）。

### 4.3 锚点维度
- 说话人(角色码)+normalize 双约束锚点正确率 99.8%（旧 normalize 唯一 99.9%，提升不大）。
- **长句唯一匹配本就可靠，说话人约束的价值在短句消歧 + 差分分支，不在锚点**。

## 五、差分对话 & 说话人约束

### 5.1 差分对话占比
- EVO 里「(角色码,normalize) 多 voice_id」**5.1%**（1,376/26,779），台词条数 13.2%。
- 主要角色码：001 艾丝蒂尔 399、002 约修亚 258（差分主要发生在主角）。

### 5.2 差分对话的两种形式
- **Remake**：同一 `(speaker,text)` 重复 2 次（TK_xxx 里 2,888 处，95% 重复 2 次），靠 flag 分支区分。
- **EVO**：`Switch(EXPR_GET_RESULT, case N→剧情块)`，核心 NPC 台词「文本同 voice_id 不同」（如 0860000952 vs 0860000967），主角差分「文本不同」。

### 5.3 说话人约束（强约束）
- `speaker_map`：Remake speaker → EVO 角色码（0→001 艾丝蒂尔、1→002 约修亚、10001→109 伊达、10005→086 帕特、10007→085 鲁克）。
- 小数字=主角/常规角色，10000+=NPC。
- **约修亚的台词不能用艾丝蒂尔的声音**——匹配时 speaker 必须对应。

### 5.4 差分核心台词「无法唯一确定」
- Remake 把差分对话「核心合并、差分部分保留分支」：`Loc_50` 是两个 case 的**汇合点**（`Loc_86 jump→` + `Loc_49 next→`）。
- 核心台词（如 `'うわわあああん'`）在 Remake 只出现一次，case 信息丢失，两个 voice_id 映射到同一句，**理论上无法唯一确定**（只能集合命中交给人工/LLM 二选一）。

### 5.5 短句复用 gt 跨角色
- `'まあね。'` speaker=001(艾丝蒂尔) 但 gt 角色码=032；`'どうしたの？'` speaker=086 但 gt=002/001。
- **短句复用的 gt 匹配没保证说话人对应**，是噪声；speaker 硬过滤正确排除它们（该 speaker 在 EVO 无语音）。

## 六、TK_xxx 选项菜单（人物对话）

### 6.1 结构占比
- TK_xxx 共 1,095 个：**纯对话框选项(LoadResult) 66%**、单次对话(无条件跳转) 31.8%、混合 1.9%、纯剧情 flag 0.3%。

### 6.2 Remake 侧特征
- **只存 NPC 回应**（Cmd_text speaker 全 NPC），主角台词被抽成「话题」。
- 话题存菜单资源（flag→话题表），**不在 mp 脚本里**。
- add_struct 两种：`id=321+array2=[INT(flag)]`（话题项）vs `id=-1+array2=[INT(5),INT(0),speaker,文本]`（台词语音结构）。

### 6.3 EVO 侧特征
- 剧情块（Switch case + ChrTalk 连续对话），**主角+NPC 对话放一起**（同一个块里 001/002/085/086 都在）。

### 6.4 异构结论
- Remake 把 NPC 对话「选项化/菜单化」，EVO 是「剧情块」，**两边异构**。
- **TK_xxx 不能走图匹配**（结构异构），只能靠角色码 hint + 文本。

## 七、句级精化（块内夹逼）

### 7.1 段内夹逼 bug（重要）
- 命中判定 `cand[0](voice_id) in gt(EVO块)` **类型不一致**，导致假「0 命中」。
- 修正为 `vid_to_evoblk[cand[0]] in gt` 后，**段内唯一 0% → 98.6%**（3,713/3,764）。

### 7.2 句级精化真实水平（修正后）
| 类别 | 结果 |
|------|------|
| 锚点唯一 | 99.5%（16,277/16,354） |
| 段内唯一 | 98.6%（3,713/3,764） |
| 段内多候选 | 0/2,405 |

### 7.3 候选空归因
| 类别 | 数量 | 性质 |
|------|------|------|
| A. 段无 EVO 块（块级对齐失败） | 3,516 | **根因=Switch case 多 case 候选不唯一** |
| B. 该角色该文本无语音 | 1,159 | 边界（正常） |
| C. 有语音但不在段 EVO 块内 | 864 | 段约束过严/对齐偏 |

### 7.4 A 类根因
- TK_xxx 的 `_entry` 有锚点，但 `cond_false` 边（选项分支）MIRROR 到 EVO 的 `switch`（Switch case），**多 case 候选不唯一**，传播断在第一步。
- 无锚点块串（`Loc_291→292→...→312`）整串靠这一步带起来，一步断整串断。

## 八、能力边界总结（最终结论）

| 类型 | 处理方式 | 水平 |
|------|---------|------|
| 非 TK_xxx（剧情流 EV_xxx/chr_xxx） | 图匹配（块对齐+传播+段内夹逼） | 句级 98%+ |
| TK_xxx（选项菜单） | 跳过图匹配，角色码+文本定位 | 异构，无法图匹配 |
| 无语音（B 类） | 边界 | 无法定位（正常） |
| 差分核心台词（多候选） | 边界 | 理论上无法唯一（Remake 合并差分） |

### 8.1 匹配维度（最终）
1. **说话人（speaker→角色码）**：强约束，锁死「谁说的」，约修亚≠艾丝蒂尔
2. **文本 normalize**：主键粗筛
3. **分支（Switch case / flag）**：区分差分对话
4. **块归属 + region/seq**：句级夹逼定位

### 8.2 下一步
按函数类型分流：TK_xxx 走角色码+文本定位，非 TK_xxx 走图匹配，出端到端精度。

## 九、函数级对齐突破（块级对齐失败的真解）

### 9.1 关键发现
漏掉的 2564 句里，**99%（2028 句）文本几乎相同（编辑距离 ≥90）**，根本不是文本改写，而是**块级对齐失败**——孤立块（函数入口 `_entry`）无前驱、段 evo_blk=None，导致段内候选空。

### 9.2 漏掉句根因（非 TK 1857 句）
- 无前驱孤立块 1,160（函数入口 _entry，传播无从下手）
- 前驱无锚点串 503（连续无锚点块，传播链断）
- 前驱有锚点但候选不唯一 259

### 9.3 解法：函数级对齐 + 短句精化
```
函数级对齐：函数内长句锚点（角色码+文本唯一）投票到 EVO 函数
  → 356/531 函数（67%）能唯一对齐
短句精化：函数内短句，在「EVO 函数内该角色 voice_id」里编辑距离选最像
  → 救回 798（阈值80，97.4% 正确，21 错配）
```

### 9.4 最终成果
- 块级对齐 + 段内精化：唯一 23,840（51.8%）
- + 函数级对齐救回 ~800：唯一确定率 ≈ **53.5%**
- 错配仅 21（阈值 80）

### 9.5 能力边界（最终）
- 无语音（Remake 改写 / Evo 未配音）46.5% 是硬上限
- 省略号复用、additional_voice、词语级文本改写是理论边界
- 结构化匹配极限约 53.5% 唯一、零错配（可接受少量错配换救回）
