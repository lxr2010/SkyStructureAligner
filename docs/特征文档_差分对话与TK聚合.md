# Remake vs EVO 特征文档：差分对话 & TK_xxx 聚合场景

> 空轨 1st Remake（新）↔ EVO（旧）结构匹配的关键差异分析
> 生成日期：2026-08-28

---

## 一、差分对话（同一 NPC 同一场景，换用不同角色/选项，台词有细微区别）

### 1.1 定义
空轨的差分对话 = 同一 NPC、同一场景，因「换用不同角色对话」或「对话选项不同」，台词产生细微区别。区别分两种：
- **文本区别**：台词文本不同（如「艾丝蒂尔单独突入」 vs 「约修亚配合」）
- **语音区别**：台词文本相同，但 voice_id 不同（同一句、不同语音，换用角色导致）

### 1.2 Remake 侧特征

| 特征 | 说明 |
|------|------|
| 表示方式 | 同一 `(speaker, text)` 重复出现，靠 `flag` 分支区分 |
| 重复规模 | TK_xxx 里 2,888 处，**95% 是重复 2 次**（对应 EVO 的 Switch case 0/1） |
| 重复主体 | 主要是**主角台词**（speaker 0 艾丝蒂尔 426 处、speaker 1 约修亚 232 处） |
| 文本类型 | **95% 是长句**（短句只有 142 处，短句复用是另一回事） |

**例子**（TK_LOOK）：
```
[1] speaker=0(艾丝蒂尔) 'まあね。'
[2] speaker=0(艾丝蒂尔) 'まあね。'      ← 重复 = 差分分支
[29] speaker=1(约修亚) 'だから…'
[30] speaker=1(约修亚) 'だから…'        ← 重复
```

### 1.3 EVO 侧特征

| 特征 | 说明 |
|------|------|
| 表示方式 | `Switch(EXPR_GET_RESULT, (case N, "loc_x"), …)` 多分支 |
| 分支内容 | case 指向**剧情块**，块内含 ChrTalk 连续对话 |
| 核心台词（NPC） | **文本相同 + voice_id 不同**（角色码相同、seq 不同） |
| 差分部分（主角） | **文本不同 + voice_id 不同** |

**例子**（C0412 Function_3 的 Switch）：
```
Switch(
  (EXPR_GET_RESULT, EXPR_END),
  (0, "loc_5CC"),     ← 差分版本1（艾丝蒂尔主导）
  (1, "loc_105E"),    ← 差分版本2（约修亚配合）
  (SWITCH_DEFAULT, "loc_1A0A"),
)
```
两个版本的核心 NPC 台词文本相同但 voice_id 不同：
```
loc_5CC : [086]'うわわあああん…'  voice_id=0860000952
loc_105E: [086]'うわわあああん…'  voice_id=0860000967   ← 文本同、语音不同
```

### 1.4 说话人约束（最关键）

- **speaker_map** 把 Remake speaker 映射到 EVO 角色码：
  ```
  Remake speaker 0  → 角色码 001（艾丝蒂尔）
  Remake speaker 1  → 角色码 002（约修亚）
  Remake speaker 10005 → 角色码 086（帕特 PAT）
  ```
- **强约束**：说话人在新旧两侧严格对应。约修亚（speaker=1）的台词只能配角色码 002 的 voice_id，**绝不能配 001 艾丝蒂尔的声音**。
- **实证**：TK_LOOK 里 speaker=0 的 `'まあね。'`，EVO 里 `'まあね。'` 的 voice_id 却是角色码 003（雪拉扎德）/032——**光看文本会错配，必须 speaker 约束排除**。

### 1.5 差分台词可能无语音

- 艾丝蒂尔（001）的 `'まあね。'` 在 EVO 里**没有对应 voice_id**（差分台词无语音）
- 有语音的 `'まあね。'` 是 003/032 说的，与 TK_LOOK 这场戏无关
- **结论**：匹配必须「文本 + 说话人」双重命中才可靠，差分里那条无语音的天然匹配不上，不能硬凑

## 二、TK_xxx 聚合场景（人物对话函数）

### 2.1 定义
Remake 把某个 NPC（或场景）的对话**聚合成一个选项菜单函数**（TK_xxx），而 EVO 里这些对话**分散在多个场景/剧情块**里。

### 2.2 Remake 侧特征

| 特征 | 说明 |
|------|------|
| 函数类型占比 | **纯对话框选项 66%**（LoadResult）+ 单次对话 31.8% + 剧情 flag 仅 0.3% |
| 选项机制 | `flag(编号)` + `JumpWhenFalse(LoadResult)`，每个 flag 对应一个话题 |
| 台词内容 | **只有 NPC 回应**（Cmd_text，speaker 全是 NPC） |
| 主角台词 | 被抽成「话题文本」，存菜单资源（flag→话题表），**不在 mp 脚本里** |
| add_struct 结构 | `id=321 + array2=[INT(flag)]`（话题项）vs `id=-1 + array2=[INT(5),INT(0),speaker,文本]`（台词语音结构） |

### 2.3 EVO 侧特征

| 特征 | 说明 |
|------|------|
| 结构 | **剧情块**（Switch case + ChrTalk 连续对话） |
| 对话组成 | **主角 + NPC 对话放一起**（同一个块里 001/002/085/086 都在） |
| 选项 | Switch 多分支（case N → 剧情块） |

**对比**（TK_PAT 的对话）：
```
EVO  (C0412 Function_3/loc_5CC)：001'いけないっ！' 002'エステル！' 085'あっち行け' 086'うわわあああん'…
Remake(TK_PAT)：只有 speaker=10005(PAT) 的 6 组回应，主角台词 → 话题表
```

### 2.4 聚合程度（gt 统计）

| TK_xxx | 有 gt 台词 | 去重 EVO 场景 | 主要角色码 |
|--------|-----------|-------------|-----------|
| TK_PAT | 1 句 | **9 个场景** | 002/001（主角） |
| TK_LOOK | 4 句 | **16 个场景** | 032/006/118/052（多角色） |
| TK_IDA | 25 句 | 3 个场景 | **109（伊达）为主** |
| TK_RADOMIRA | 3 句 | 3 个场景 | 001/002（主角） |

**结论**：
- TK_xxx 聚合的 EVO 场景差异很大（TK_LOOK 聚合 16 个场景，TK_IDA 只 3 个）
- **有 gt 的台词很少**（大部分是 Remake 改写的，文本对不上）
- 角色组成不一：NPC 为主（TK_IDA）、主角为主（TK_PAT）、多角色（TK_LOOK）

## 三、对结构匹配的指导

1. **函数分流**：
   - `TK_xxx`（人物对话，~60%）→ **跳过图匹配**，用「角色码 hint + 文本 + 说话人」定位
   - `EV_xxx / chr_xxx`（剧情流，~40%）→ **图匹配**（同构，块图对齐有效）

2. **匹配维度（双约束，说话人优先）**：
   - 第一约束：**说话人**（speaker → 角色码 → voice_id 前 3 位）
   - 第二约束：**文本**（normalize）
   - 第三约束：**分支**（Switch case / flag）区分差分对话

3. **差分对话处理**：
   - 同一 `(speaker, text)` 重复的台词，**不能当唯一锚点**（会错配到差分另一条）
   - 差分核心台词（NPC）文本同 voice_id 不同 → 用「说话人 + 分支」区分
   - 差分台词可能无语音 → 匹配不上属正常，不硬凑

4. **Switch 边类型**：EVO 的 Switch case 分支要纳入边类型（当前只提了 Jc/Jump，漏了 Switch）
